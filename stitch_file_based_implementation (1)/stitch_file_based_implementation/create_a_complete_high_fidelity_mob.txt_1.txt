============================================================
01. NEW SYSTEM CONCEPT
============================================================

Campus Event has three main user roles:

1. USER
2. EVENT LEADER
3. ADMIN

There must also be an explicit permission system.

USER:
- Can browse events.
- Can register for events.
- Can view registered events.
- Can receive digital tickets.
- Can use QR ticket for check-in.
- Cannot create events by default.
- Cannot manage other users.
- Cannot approve events.

EVENT LEADER:
An Event Leader is a user who has been granted event-management permission by an Admin.

Event Leader can:
- Create events.
- Edit their own events.
- Submit events for approval.
- View approval status.
- Manage event information.
- View registered participants.
- Generate event QR check-in.
- View check-in status.
- Assign selected users as CHECK-IN STAFF for their event.
- Revoke check-in permission from those users.
- Perform QR check-in.

ADMIN:
Admin has system-level management permissions.

Admin can:
- View system dashboard.
- Manage users.
- Search users.
- View user details.
- Grant or revoke Event Leader permission.
- Grant or revoke Check-in Staff permission where appropriate.
- Review submitted events.
- Approve events.
- Reject events.
- Request changes.
- Manage published events.
- View event statistics.
- Monitor check-in activity.

IMPORTANT:
Do NOT make Admin simply a visually different Profile page.

Admin must have a dedicated management experience.
